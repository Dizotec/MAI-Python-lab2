# ЛР 2. Потоковый анализатор файлов

`streamstats` читает CSV, JSONL и бинарные записи, проверяет события и создаёт статистический отчёт. Требуется Python 3.12+.

## Установка и запуск

Установка зависимостей — из корня проекта, в активном виртуальном окружении. Запуск программы — из папки `src`:

```powershell
python -m pip install pytest ruff pre-commit -r requirements.txt
cd src
python -m streamstats --help
python -m streamstats analyze test_ok.jsonl --format jsonl
python -m streamstats analyze test_ok.csv --format csv --output report.json
python -m streamstats analyze test_ok.jsonl test_ok.jsonl --format jsonl
python -m streamstats analyze test_bad.jsonl --format jsonl --skip-invalid
```

Порядок фиксирован: `analyze INPUT... --format FORMAT [--output FILE] [--start ISO] [--end ISO] [--level LEVEL] [--source SOURCE] [--follow] [--skip-invalid]`. Необязательные параметры можно пропускать. Аргументы разбираются вручную. Явный `--format` определяет формат всех входов, независимо от расширения. Повторно переданный файл обрабатывается повторно.

Без `--output` результат выводится в stdout. Диагностика и WARNING идут в stderr. Коды завершения: 0 — успех, 2 — ошибка, 130 — прерывание обычного анализа. Выходной файл не может совпадать с входным.

## Принятые допущения

- Флаги идут в фиксированном порядке, как указано выше.
- Дата без пояса считается UTC, границы отчёта — минимум и максимум времени.
- Follow читает один JSONL-файл; запись заканчивается переносом строки.
- Бинарный формат выбран для этой работы: четыре длины и четыре поля UTF-8.
- При неверном CSV-заголовке или бинарной сигнатуре обработка останавливается.

## Событие

Обязательные поля: timestamp, level, source, message. Все значения должны быть строками. Допустимые уровни: DEBUG, INFO, WARNING, ERROR, CRITICAL. Source не может быть пустым; пробелы вокруг него удаляются. Message может быть пустым, его содержимое сохраняется.

Timestamp разбирается как ISO 8601 и приводится к UTC. Отсутствующий пояс означает UTC, дата без времени — полночь UTC. Поэтому `2026-10-24` в старом примере `test_bad.*` допустима. Границы отчёта — минимальное и максимальное время среди учтённых событий.

JSON-отчёт содержит total_events, levels, sources, top_5_error_sources, first_timestamp, last_timestamp и skipped_lines (при наличии пропусков или в режиме --skip-invalid). По умолчанию выводятся пять источников ERROR/CRITICAL. При равных значениях источники сортируются по имени. Для пустого входа счётчики пусты, количество равно нулю, даты равны null.

В строгом режиме обработка останавливается с указанием файла, строки и причины. В режиме пропуска повреждённая запись даёт WARNING и увеличивает skipped_lines. Для CSV с переносами внутри кавычек указывается первая физическая строка записи. Пустые строки JSONL и пустые строки между CSV-записями игнорируются. Неправильный CSV-заголовок — ошибка файла.

## Дополнительные задания

Команды запускаются из папки `src`.

### Ленивые фильтры

```powershell
python -m streamstats analyze test_ok.jsonl --format jsonl --start 2026-10-24T10:05:00Z --end 2026-10-24T10:20:00Z --level ERROR --source database
```

Границы включаются. CLI принимает один уровень и один источник. Между фильтрами действует «и». Отфильтрованное событие не считается ошибкой; отметки SKIP проходят через фильтры для подсчёта пропусков.

### Реестр парсеров

В `parsers.py` функция `register_parser(name, function)` добавляет новый формат. Парсер принимает `(file, skip_invalid_flag)` и выдаёт события или строку SKIP. Общая функция `parse_text_lines` выполняет валидацию и обработку ошибок текстовых записей.

После регистрации формат выбирается через `stream_events(..., format_name=name)`. Полный пример пользовательского формата `timestamp|level|source|message` находится в `test_custom_parser_registry` в `tests/test_parsers.py`. Добавление формата не требует изменения расчёта или отчёта.

### CSV-отчёт

```powershell
python -m streamstats analyze test_ok.jsonl --format jsonl --output report.csv
```

CSV выбирается расширением `.csv` выходного файла. Колонки: section, name, value. JSON и CSV используют один рассчитанный словарь. Размер топа задаётся аргументом `top_n` функции `statistics`; по умолчанию 5.

### Измерение памяти

```powershell
python -m streamstats.analysis
```

Выполнено 03.11.2026, Python 3.14.7, Windows. Генерация идёт блоками до начала измерения; tracemalloc включается только на время анализа. Вход содержит один источник. Временный файл удаляется после запуска.

| Размер входа, байт | Событий | Пик tracemalloc, байт | Время, с |
|---:|---:|---:|---:|
| 524 288 534 | 558 943 | 154 087 | 9,270 |

Вход превышает 500 МБ и 500 МиБ. Измерены выделения Python, а не вся память процесса. Результат зависит от среды. Функция `memory_benchmark(size)` принимает размер в МиБ; по умолчанию 500. В тесте используется 1 МиБ, чтобы не создавать большой файл при каждой проверке.

Дополнительная память — O(S + R): S — количество уникальных источников, R — размер текущей записи. При росте числа источников растут словари счётчиков. Все события в памяти не сохраняются. Сортировка источников для топа занимает O(S log S) времени и O(S) памяти.

### Слежение за дописываемым файлом

```powershell
python -m streamstats analyze test_ok.jsonl --format jsonl --follow
```

Поддерживается один JSONL-файл. Сначала читается имеющееся содержимое, затем итератор `follow_lines` ждёт новые полные строки. Незавершённая строка, включая неполный UTF-8 символ, ожидает дописывания. Ctrl+C завершает слежение и сохраняет накопленный отчёт. Неполная строка при остановке не учитывается. Ротация и обрезание файла не поддерживаются.

### Бинарный формат через memoryview

`--format binary` читает SSB1. Файл начинается с четырёх байт `SSB1`. У каждой записи заголовок `struct.Struct("<IIII")`: четыре длины полей в байтах UTF-8, по 4 байта на длину, little-endian. После заголовка подряд записаны timestamp, level, source, message.

Читается одна запись с ограничением размера 16 МиБ. Через memoryview выделяются части общего буфера для каждого поля. Срезы не копируют исходные байты; декодирование создаёт строки Python. Проверка события общая с CSV и JSONL. Номер строки в диагностике означает номер бинарной записи.

Пример формирования бинарной записи находится в `binary_row` в `tests/test_parsers.py`. Запуск: `python -m streamstats analyze INPUT.bin --format binary`.

Неверный уровень, дата или UTF-8 обрабатываются по выбранному режиму. Усечённая последняя запись даёт один пропуск. Неверная сигнатура и превышение лимита размера — ошибки файла.

## Структура и проверка

Сохранены семь модулей из задания: models.py — событие и проверка, parsers.py — парсеры и слежение, analysis.py — статистика, фильтры и замер памяти, report.py — отчёты, errors.py — исключения, __main__.py — CLI, __init__.py — пакет.

Проверки выполняются из корня проекта:

```powershell
python -m pytest -q
python -m pytest --cov=streamstats --cov-report=term-missing
ruff check .
ruff format --check .
pre-commit run mypy --all-files
cd src
python -m streamstats --help
```

30 тестов проверяют оба парсера, ошибки в двух режимах, пустые файлы, Unicode, несколько входов, временные границы, top-N, CLI, фильтры, реестр, CSV-отчёт, бинарные записи и дописывание файла. Тестовые файлы создаются во временных каталогах.

Покрытие всего пакета, включая CLI в дочерних процессах: 93,96% строк, 89,19% ветвлений, общий показатель 92,58%. Исключённых строк нет. В pyproject.toml задан порог 81%.

Для защиты: новый уровень добавляется в LEVELS в models.py. Top-N задаётся аргументом top_n у statistics. Исходные имена ключей top_5_sources и top_5_error_sources сохранены. Построчное чтение находится в parse_text_lines и csv.reader; бинарное чтение — в parse_binary.
